## Session expiration and refresh

Nuxt OIDC Auth automatically checks if the session is expired and refreshes it if necessary. You can disable this behavior by setting `expirationCheck` and `automaticRefresh` to `false` in the `session` configuration.
The session is automatically refreshed when the `session` object is accessed. You can also manually refresh the session using `refresh` from `useOidcAuth` on the client or on the server side by calling `refreshUserSession(event)`.

Session expiration and refresh is handled completely server side, the exposed properties in the user session are automatically updated. You can theoretically register a hook that overwrites session fields like `loggedInAt`, but this is not recommended and will be overwritten with each refresh.

## Using the session in server side code

You can access the user session in your server side code by using the `getUserSession` function from `nuxt-oidc-auth`.

```ts
import { getUserSession } from 'nuxt-oidc-auth/runtime/server/utils/session.js'

export default eventHandler(async (event) => {
  const session = await getUserSession(event)
  return session.userName
})
```

By default, `getUserSession` and `refreshUserSession` throw an HTTP `401` when the session is invalid or expired and cannot be refreshed.

For API/XHR handlers, you can explicitly choose error behavior:

```ts
import { getUserSession } from 'nuxt-oidc-auth/runtime/server/utils/session.js'

export default eventHandler(async (event) => {
  const session = await getUserSession(event, { errorBehavior: 'throw' })
  return { user: session.userName }
})
```

Use `{ errorBehavior: 'redirect' }` when you want legacy redirect behavior instead of an HTTP error.

Be careful to not expose any sensitive information from the handler code.

## Calling APIs with the access token

Use `getAccessToken` in a server handler to call an API on behalf of the signed-in user. It reads the access token from the encrypted server side token store, so it works with `exposeAccessToken: false` and the token never has to reach the browser.

The token store has an entry when the provider returns a refresh token, or when `exposeAccessToken` or `exposeIdToken` is enabled. For providers without refresh tokens that keep both exposure flags disabled, enable `storeAccessToken` so the access token is stored for server side use only:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  oidc: {
    providers: {
      oidc: {
        storeAccessToken: true,
      },
    },
  },
})
```

Every stored token is encrypted with `NUXT_OIDC_TOKEN_KEY`. Set the same key on all server instances and use a storage driver for the `oidc` storage that all instances share, otherwise a request that lands on another instance or follows a restart can't read the token. See [security](/getting-started/security#configure-secrets) for the secrets. Logout removes the token record; browser session expiry alone does not remove it.

```ts [server/api/orders.get.ts]
import { getAccessToken } from 'nuxt-oidc-auth/runtime/server/utils/session.js'

export default eventHandler(async (event) => {
  const accessToken = await getAccessToken(event)
  return await $fetch('https://api.example.com/orders', {
    headers: { Authorization: `Bearer ${accessToken}` },
  })
})
```

`getAccessToken` returns a promise for the raw token string. It validates the session the same way as `getUserSession`. With `expirationCheck` and `automaticRefresh` enabled and a refresh token available, it refreshes an expiring token before returning it. The stored token expires at its `exp` claim. For opaque tokens it expires `expires_in` seconds after sign-in, and if the provider sends neither, after the session `maxAge`.

It throws an HTTP `401` when:

- the session is invalid, or expired and can't be refreshed
- the session has no stored access token, for example because the provider issued no refresh token and `storeAccessToken` is disabled. Sessions created by an earlier version without a refresh token also require the user to sign in again
- the stored access token has expired or has no expiry after any permitted refresh attempt
- the stored access token can't be decrypted, for example after `NUXT_OIDC_TOKEN_KEY` changed

Only return data from the API response. Never return the token itself from your handler.
